Skills, in order: existing repo, /map → /spec → /plan → build → /walkthrough → /code-review (/setup alongside /map); new project, /spec → /plan → build → /setup → /walkthrough, then /code-review from the first PR on (the skeleton's first commit is local, so there is no PR to review yet). /walkthrough comes first because it is your own review: you answer before Claude does. /code-review comes last, after the branch's final commit and before the PR opens: it reviews the branch's changes against the base branch, you fix or decide on each finding, and the findings go in the PR's Review section. Run it again if the fixes changed code. It replaces automated PR review in CI. Each cell says where its skill fits; using them is a general recommendation, not yet confirmed as required. How Claude follows a workflow · detours, switches, recaps, the decisions file

Type. You name the workflow, or Claude proposes one from your description and you confirm. A small, obvious task needs no type and no file.

A phase is a position, not a permission. Claude never refuses an edit because of the phase, and never says "you can't go back". Quick changes are always allowed.

Detour (a small change that fits another type, such as a visual tweak during a bug fix): Claude does it, says so in one line, and adds a note under Detours and switches in the decisions file. No interview.

Switch (the next steps would change: a new spec, a new risk, a different checkpoint): Claude pauses and asks short questions, each with a purpose line, such as "Do you need more understanding first? Use this if you're unsure what the code does." It may skip questions that don't apply, but says which and that going back is an option.

Every phase transition gets a four-part recap: what happened; evidence the checkpoint was met; why it's fine to move on; what you should understand now. Claude names the finished and the next phase, suggests the command that fits best (this setup's or a built-in), and waits for your OK.

Decisions file. docs/workflow/<topic>-decisions.md is committed and carries Branch, Type, Phase and Detours and switches. Claude creates it when the task gets a branch or the first decision worth keeping comes up, whichever is first, and says so. At session start Claude reads the decisions files whose Branch equals the current git branch and tells you if that task is mid-phase.

Claude reads these from .claude/rules/workflow-types.md and the workflow-types skill, which are installed with the template. This guide is not copied into other repos.
